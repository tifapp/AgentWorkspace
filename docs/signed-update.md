# Signed update protocol

Production packaging requires a trusted Code Signing certificate with an accessible private key in CurrentUser/My or LocalMachine/My. Its subject must exactly match the MSIX Publisher, it must be time valid, have the Code Signing EKU, and build a trusted chain. No script generates or installs a certificate. Supply Windows SDK MakeAppx and SignTool paths when discovery fails, and `-DotnetPath` to an installed .NET 10.0.401 SDK. `-ArtifactsOutput` must be a dedicated folder outside the repository, workspace, and running installation. `-UnsignedDiagnostic` is for diagnosis only; updates reject it.

The signed MSIX contains `update-protocol.json` with protocol 1, state schema 2, and hashes of both packaged Core assemblies. The external package manifest repeats those values and records package SHA256, signer, publisher, identity and version. The updater compares signed and external metadata, verifies Authenticode and signer trust, checks x64 and minimum OS, and requires a strictly newer version. The installed metadata root needs `package-manifest.json` with `PackageFile`, `Sha256`, `Version`, `IdentityName`, `Publisher`, `SignerThumbprint`, `InstallLocation`, and `PackageFamilyName` for a still available prior signed MSIX. Update is unavailable when the prior signed package cannot be verified for rollback.

Run `scripts/update-agentos.ps1` with `-Package`, `-Manifest`, `-InstallRoot`, `-Project`, `-CliPath`, and `-TrustedSignerThumbprint`. `-VerifyOnly` stops after package and prior package verification. The installed CLI is `cli/AgentOS.Cli.exe` in the target MSIX. The current user named pipe accepts fixed health, drain, readiness, map cancellation and exit operations. A drain binds a random token to the exact signed package hash, version, x64 architecture, installation and owning project. New work, map launches, publication requests and external execution are rejected during drain; active authorized work may finish or be canceled by its user. Readiness blocks active work, owned jobs, publication writers, selected map tasks still waiting to launch, unknown outcomes and external effects. The updater does not cancel work or close other projects. For selected tasks still waiting to launch, the project owner can run `AgentOS.Cli.exe update-cancel-map <project> <map-id>`; launched work continues.

The updater backs up the prior signed package and metadata, stages a verified candidate, and inventories project state references. If readiness is blocked, rerunning the same package reuses the saved candidate and drain scope. If the owner exited before installation could start, reopen the prior installed app and rerun the same package; its saved drain still refuses new work. It calls `Add-AppxPackage` after cooperative exit releases the project lock and AgentOS processes have stopped. The new CLI must pass protocol, schema, capability and binary hash handshake before the packaged runtime is restarted for the exact project and its new owner health is confirmed. Failure rolls back with the prior signed MSIX only when state generation, schema, complete state inventory, and stopped process checks permit it. Otherwise `update-state/pending.json` records `RecoveryRequired`. Journals are never restored or downgraded.

Machine prerequisites include MSIX deployment commands, a trusted publisher certificate, Windows SDK packaging tools, a .NET 10.0.401 SDK, prior signed package and installed metadata, and an open schema 2 project runtime. A production signed package is still required. This source change does not install the app.
