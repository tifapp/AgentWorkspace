# Signed MSIX update protocol

`scripts/package-signed.ps1` builds a production package only with a trusted Code Signing certificate and accessible private key whose subject matches the MSIX Publisher, valid Code Signing EKU and chain. Provide Windows SDK MakeAppx/SignTool and .NET 10.0.401 paths when discovery fails. `-ArtifactsOutput` must be a dedicated location outside the repository, workspace and running installation; the script rejects overlaps and reparse traversal. No certificate is generated or installed. `-UnsignedDiagnostic` creates a diagnostic package only; the updater rejects it. The side-by-side portable `artifacts/release/agent-os-integrated-win-x64` folder/ZIP from `scripts/build.ps1` is a separate unsigned path.

The signed package embeds `update-protocol.json` with protocol 1, **state schema 3** and Core hashes for both App and CLI. The external manifest repeats these and records package SHA-256, signer, publisher, identity and version. `scripts/update-agentos.ps1` verifies Authenticode trust, external/embedded metadata, x64/minimum OS and strictly newer version. Prior installed metadata must identify an available verifiable signed MSIX for rollback; an old portable retirement bundle does not satisfy this prerequisite.

The updater accepts `-Package`, `-Manifest`, `-InstallRoot`, `-Project`, `-CliPath` and `-TrustedSignerThumbprint`. `-VerifyOnly` stops after verification. The installed CLI is `cli/AgentOS.Cli.exe` within the signed package. Its same-user broker offers protocol health, scoped drain, readiness, selected-map cancellation and cooperative exit. The drain binds a token to exact package hash/version/architecture/install/project. It rejects new work, map launches, publication and external execution; it does not silently cancel active work. The owner may cancel selected map nodes not yet launched with `update-cancel-map`.

Readiness checks active work, owned jobs, publication writers, unlaunched selected map tasks, unknown outcomes and external effects. After cooperative exit releases the project lock, the updater installs the verified candidate and requires CLI protocol/schema/capability/Core-hash handshake plus new runtime health. Failure can restore the prior signed package only if state generation, schema, refs and stopped-process inventory still permit rollback. Otherwise it records `RecoveryRequired`; journals are not downgraded. No production signing, install, update or rollback was executed in this session.
