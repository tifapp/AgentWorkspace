# Desktop interactions

The live Settings > Advanced controls open Maps, Capture context into map, Work interactions and External effects. Task menus open interactions scoped to the selected task. `--ui-preview` provides visual/control inspection only: it does not create a real capture controller, global hotkey, project runtime or effect action.

Capture retains an external foreground HWND, PID and process creation identity. The review shows bounded UIA text and an optional screenshot with explicit crop. Opening CaptureDialog automatically requests three Codex suggestions when checked visible text or an explicitly included applied screenshot crop is available; included-context and CLI path changes debounce for 600 ms. The checked context is sent to the configured Codex account. Draft prompt, title, acceptance and map edits remain independent of generation. Refresh and Cancel remain available, and stale results are discarded. Each vertical suggestion row has a keyboard-operable Start task button. Clicking it explicitly authorizes immediate launch of that suggestion in a separate one-task map with the exact included context; the draft editor remains open. Uncertain save and start outcomes are reconciled by stable map/task identity before retry. Existing draft save and review/start remain separate. Accepted text/image bytes are immutable and hashed. At explicit task start, text bytes enter untrusted `additionalContext`; PNG bytes enter `input` as an image data URL with untrusted provenance. Captured content cannot supply instructions or authority.
Maps displays a draggable, zoomable canvas with task cards, dependency/related/followup edges, layout, citations and attempt lineage. Draft edits save with revision checks; cycles and missing dependencies are refused. Selecting explicit task IDs authorizes the dependency-closed graph: every unfinished dependency must be selected or already authorized. Ready roots start immediately; selected dependents remain durable pending nodes and start when prerequisites complete. Further active-map selections preserve earlier pending authorizations. Task result citations and manually added nodes are supported. The status follows actual task outcomes.

Work interactions reads the durable task journal. Active tasks can receive steering; a reply after completion creates a child followup with parent lineage. Clarifications can be answered, peer requests acknowledged or handed to another active task, waits inspected/resolved/canceled, required obligations resolved, and followup proposals accepted or rejected. Proposals never auto-start. The inbox and acknowledgement are scoped to exact work/interaction IDs.

External effects opens separate prepared-scope review. Approval is bound to the displayed digest; execution and reconciliation require configuration and explicit actions. Notification history, quiet hours, tray navigation and close guard are local desktop controls. No external credentials or effects were exercised here.

Native App build 73d completed with zero warnings/errors. UIA controls and bounds were verified at wide and narrow preview sizes. Screenshots from the current session and retained 3fbb baseline are blank, so rendered visual appearance is unverified. The external WinForms fixture and authenticated synthetic drafting proof are described in [validation report](validation-report.md).
